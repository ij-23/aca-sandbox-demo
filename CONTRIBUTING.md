# Contributing

Read [AGENTS.md](./AGENTS.md), [README.md](./README.md) and the current
[compatibility ledger](./docs/compatibility.md) before changing integrations.
Use the README developer commands for platform tests, frontend build and the
network-isolated application container check. Keep generated JSON schemas in sync
with the Pydantic models using `scripts/export_schemas.py`.

The [fixture](./demo-repo/README.md) is deliberately vulnerable teaching code.
Do not import it, execute its tests, build it or launch it on a developer machine,
the hosting application or a CI runner. Platform pytest discovery is limited to
`backend/tests` and `scripts/tests`. Run fixture code only in a purpose-created
disposable Sandbox within the authorized project scope. Static reading and dependency-lock generation are permitted.

Unit-test doubles must stay in test files. Never label their output as an Azure,
Copilot or Dynamic Workflow result. Real replay recordings must come from a
verified A/B/C run and remain explicitly labeled prerecorded.

All Terraform work must follow the installed `terraform-builder` skill. Preserve
the already-applied foundation plan; prepare a new reviewed plan for any future
infrastructure change. Follow the [standing project authorization](./AGENTS.md#project-execution-authorization--2026-10-14)
for scoped operations; inspect exact plans and reject destructive or unrelated changes.
Credential changes and repository deletion require separate authorization. Never include PATs, Azure
tokens, state, private evidence, `.env` files or credential-bearing logs in a patch.

Report the scope, local checks, real integration evidence and outstanding gates
in each change. Update [progress](./docs/progress.md) with facts and limitations.
The project's own source is distributed under the [MIT license](./LICENSE);
third-party dependencies keep their own licenses and notices.

## Repository maintenance

The [README structure and documentation map](./README.md#repository-structure) describe
the maintained tree. [AGENTS.md](./AGENTS.md) owns implementation requirements;
[acceptance](./docs/acceptance.md) owns current verification and remaining work;
[progress](./docs/progress.md) records dated changes. Keep historical evidence dated
instead of treating old approval or failure notes as current blockers.

Before removing a file, check imports, filesystem-based loading, Docker copies,
CI, editor tasks and documentation references. An operator entry point can be used
without being imported. In particular, [smoke_workflow_runner.py](./scripts/smoke_workflow_runner.py)
is uploaded by the production Sandbox adapter, and the probe extensions and locked
SDK packages under [copilot-host](./workflows/copilot-host/) support credential/publication validation.
Keep the [report schemas](./workflows/schemas/) and [replay recording](./fixtures/replay-events.jsonl)
as checked-in contracts and genuine evidence.

| Local content | Maintenance policy |
| --- | --- |
| `.pytest_cache/`, `.ruff_cache/`, `__pycache__/`, `frontend/tsconfig.tsbuildinfo` | Disposable tool output; recreate on the next check/build |
| `.venv/`, `frontend/node_modules/`, `infrastructure/terraform/.terraform/` | Installed tools/dependencies; retain for normal development |
| `backend/static/` | Generated by the frontend build and served by FastAPI; rebuild before previewing if removed |
| `.local/` | Private deployment evidence, diagnostics and release manifests; inspect individual items, never blanket-delete |
| Terraform state/backups, private inputs and saved plans | Preserve the local state lineage and consumed foundation plan; never use a broad clean command here |

Install [requirements-dev.txt](./requirements-dev.txt) using the README's hash-checked
sync command for platform tests and smoke/operator tools. It includes the pinned Sandbox
SDK and Azure Identity dependencies; there is no separate smoke-only requirements file.
